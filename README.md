# Carotid Workbench

Веб-приложение для работы с сонными артериями: **DICOM → пути → контуры → поверхность → расчётная сетка → CFD**.

React + TypeScript + Three.js в браузере, Python/FastAPI для обработки изображений. Всё приложение собирается и запускается через Docker Compose; Swift не требуется. Исходный `CarotidSegApp/` оставлен как историческая нативная версия.

## Запуск через GitHub Codespaces

Для этого варианта нужны аккаунт GitHub, доступ к репозиторию и доступная квота Codespaces. Устанавливать Docker, Python или Node.js на свой компьютер не нужно — приложение работает в облачном окружении.

### 1. Создать окружение

[![Открыть в Codespaces](https://github.com/codespaces/badge.svg)](https://codespaces.new/hlarsonhlarson/carotide-segmentation?ref=main)

Нажмите кнопку выше, выберите ветку **main** и создайте Codespace. Альтернативный путь: страница репозитория → **Code → Codespaces → Create codespace on main**. Конфигурация запрашивает минимум 4 CPU и 8 GB RAM.

Дождитесь открытия браузерного редактора и завершения стартового сценария. При первом запуске он скачивает зависимости, собирает Docker-образы, запускает сервисы и создаёт синтетическое исследование. Признак готовности в выводе сценария:

```text
Demo ready on port 8080. Open project: /data/projects/demo
```

### 2. Открыть приложение и демо

1. В нижней панели редактора откройте **Ports**. Если вкладка скрыта, найдите **Ports: Focus on Ports View** через палитру команд (`F1`).
2. Найдите порт **8080** с подписью **Carotid demo** и нажмите **Open in Browser**. Если порта нет, добавьте его кнопкой **Forward a Port**, указав `8080`.
3. В приложении в поле **Папка проекта** введите `/data/projects/demo`.
4. Нажмите **Открыть проект**. Выберите правую сторону и ветвь **CCA → ICA**.
5. На вкладках **Пути**, **Контуры** и **Геометрия** уже доступны разметка, контуры, поверхность и сетка. На вкладке **Геометрия** нажмите **Показать сохранённую геометрию**, чтобы увидеть модель.

Используйте адрес из **Ports**, а не `localhost:8080` на своём компьютере: приложение запущено в Codespace.

### 3. Дать ссылку товарищу

В **Ports** нажмите правой кнопкой на порт **8080** → **Port Visibility → Public**, затем **Copy Forwarded Address**. Отправьте скопированный адрес товарищу: он сможет открыть приложение в браузере без установки окружения.

Публичная ссылка доступна любому её обладателю; авторизации внутри приложения нет. Используйте это демо только с синтетическими данными. Изменения в общем демо видны всем, поэтому лучше редактировать его по очереди. Если политика организации запрещает **Public**, товарищ может создать собственный Codespace по кнопке выше при наличии доступа к репозиторию.

### 4. Остановить и продолжить позже

После демонстрации откройте [список Codespaces](https://github.com/codespaces), найдите окружение и выберите **Stop codespace** в его меню. Закрытие вкладки браузера само по себе не является явной остановкой окружения.

Чтобы продолжить, откройте **тот же** Codespace из списка. Стартовый сценарий поднимет сервисы снова и сохранит изменения в существующем демо. Ссылку можно использовать только пока окружение работает; после возобновления проверьте доступность порта в **Ports**.

Codespaces расходует квоту GitHub и может требовать оплаты после её исчерпания. Не удаляйте окружение, если хотите сохранить работу: данные находятся в его workspace, а не в Git. Перед удалением скачайте папку нужного проекта и соответствующие снимки.

### Если что-то не запустилось

В терминале Codespace, находясь в корне репозитория, повторите стартовый сценарий:

```sh
bash .devcontainer/start-demo.sh
```

Повторный запуск не перезаписывает готовый демо-проект. Не запускайте несколько копий сценария одновременно.

Для диагностики:

```sh
docker compose ps
docker compose logs --tail=100 backend frontend
```

- **Нет порта 8080:** дождитесь запуска сервисов и добавьте порт через **Forward a Port**.
- **502 / backend запускается:** дождитесь статуса `healthy` у backend; при ошибке посмотрите его логи.
- **Проект не найден:** проверьте путь `/data/projects/demo` и завершение стартового сценария.
- **Не хватает ресурсов или квоты:** проверьте размер машины и лимиты Codespaces в аккаунте GitHub.
- **CFD недоступен:** это ожидаемо без совместимой сборки SU2; разметка и построение сетки доступны.

Стартовый сценарий использует отдельные папки `data/codespaces-dicom` и `data/codespaces-projects`, не подключая папки пациентов из локальной `.env`. Демо создаёт пример геометрии, а не фиктивные результаты CFD.

## Запуск

Нужен Docker Desktop (или Docker Engine + Compose).

```sh
mkdir -p data/dicom data/projects
# Скопируйте исследования в data/dicom/<study>/
docker compose up -d --build
```

Открыть http://localhost:8080. Снимки подключены только для чтения; проекты сохраняются на хосте в `data/projects` и переживают пересоздание контейнеров.

Для своих папок создайте `.env`:

```dotenv
DICOM_DIR=/absolute/path/to/dicom
PROJECTS_DIR=/absolute/path/to/projects
WEB_PORT=8080
```

В интерфейсе можно выбрать папку из подключённых каталогов. Пути `/data/dicom/...` и `/data/projects/...` относятся к контейнеру. Для нового проекта выбирайте отдельную пустую подпапку. Существующий проект открывается кнопкой «Открыть проект».

## Работа

- Выберите DICOM-серию, сторону и ветвь CCA→ICA / CCA→ECA.
- Рабочий экран повторяет компоновку macOS-приложения: этапы слева, аксиальный срез сверху, корональный и сагиттальный снизу, 3D-путь рядом и две колонки контрольных точек справа. Палитра взята из `Theme.swift`.
- Колесо мыши листает срезы, нажатие в режиме просмотра синхронизирует перекрестие трёх плоскостей. Кнопки +/− меняют масштаб; WL/WW управляют контрастом.
- Контуры, поверхность, сетка и CFD открываются в отдельных окнах; Escape возвращает к снимкам.
- Добавляйте, перемещайте, удаляйте и переставляйте точки. Auto-Trace строит путь между двумя выбранными точками.
- Подготовьте поперечные сечения. Доступны автоматический метод, порог, активный контур, круг и ручной многоугольник. Контуры можно обрабатывать по одному или всей серией.
- Постройте поверхность и сетку, просмотрите их в 3D, экспортируйте STL.
- Задайте граничные условия. При подключённом SU2 доступны запуск, отмена и обработка CFD; сохранённые результаты отображаются цветной 3D-картой.
- «Сохранить проект» сохраняет разметку, параметры и готовые артефакты. После выбора папки ручные изменения сохраняются автоматически.

Изменение пути/контуров сбрасывает зависимые результаты, изменение условий — CFD. Правая и левая стороны обрабатываются отдельно. Завершение вычисления не означает подтверждения физической достоверности.

## SU2: внешняя зависимость

Переданный проект зависит от кастомной сборки SU2/pysu2. Её исходников в репозитории нет. Стандартный Docker-образ запускает просмотр, сегментацию и построение сетки; CFD честно отображается как недоступный, пока не подключена совместимая **Linux-сборка** solver. macOS-библиотека pysu2 не работает в Linux-контейнере.

Соберите производный backend-образ с подходящими SU2/pysu2, Python и MPI, задайте `CAROTID_SU2_BIN` и `CAROTID_MPI_PYTHON` в окружении backend. `mpirun` должен быть в PATH. Полный расчёт требует отдельного тестирования совместимости и физики; численные настройки не менялись при переносе UI.

## Проверки

```sh
docker compose run --rm backend env -u CAROTID_DICOM_ROOT -u CAROTID_PROJECTS_ROOT python -m pytest -q
cd frontend
npm ci
npm run build
npm test
```

Локальная разработка UI: `npm run dev` (проксирует `/api` на `127.0.0.1:8000`). Контейнерный frontend проксирует API через Nginx; backend наружу не опубликован. Сервис предназначен для одного локального пользователя, без нескольких Uvicorn workers.

## Проекты и миграция

Формат v2 использует атомарный `project.json`, версии входов и отдельные неизменяемые файлы результатов. Старые файлы автоматически не удаляются. DICOM остаётся в исходной папке; перемещение снимков потребует корректировки пути в копии проекта.

Для старого неверсированного проекта:

```sh
docker compose run --rm backend python -m server.migrate_project /data/projects/old /data/projects/new
```

Исходник сохраняется. Импортируются разметка и параметры; старые CFD-результаты остаются в старой папке, поскольку их соответствие входным данным не доказано. Импортированную разметку нужно сверить со снимками.

Архитектура: `server/workflow.py` — зависимости, `server/projects.py` — сохранение, `server/storage.py` — подключённые папки; `frontend/src` — компоненты рабочего процесса. Алгоритмы находятся в `server/` и `carotid_seg/`.

Ограничения: произвольная ориентация DICOM ещё не поддерживается внутренней моделью координат; клиническая точность сегментации и физическая достоверность CFD не подтверждаются инженерными тестами. План проверки — [docs/validation.md](docs/validation.md).

Кэширование снимков и поверхностей, ускорение macOS-просмотрщика и замеры — [PERFORMANCE.md](PERFORMANCE.md).

### Сквозной браузерный тест

Синтетические данные можно создать в новой папке командой `python tests/create_demo.py data/dicom/synthetic-demo` (нужны NumPy и pydicom). Затем при работающем Docker-приложении:

```sh
cd frontend
npx playwright install chromium
npx playwright test e2e --workers=1
```

Тест создаёт отдельный проект `e2e-*`, проверяет загрузку снимков, путь, контуры, поверхность, тетраэдрическую сетку, сохранение, открытие, 3D-просмотр и сброс устаревших результатов. Эти проекты и исходные синтетические снимки не входят в Git.

Для дополнительной проверки на локальной КТ создайте JSON в игнорируемой папке `data/runtime` с полями `path` (путь к папке внутри контейнера, содержащей одну CT-серию) и `series_uid`. Запускайте из `frontend`:

```sh
CAROTID_CT_TEST_INPUT=/absolute/path/to/local-fixture.json npx playwright test e2e/ct-viewer.spec.ts
```

Этот сценарий проверяет загрузку трёх плоскостей, прокрутку, контраст и размеры окна от 390 до 1660 пикселей. Снимки экрана сохраняются локально в `data/runtime`, исходные DICOM не изменяются.
